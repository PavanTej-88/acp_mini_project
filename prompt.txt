Key Algorithm: Bresenham's Line
This is the most important algorithm here — it's also used in computer graphics professionally. The idea:

We want to go from (x1,y1) to (x2,y2) stepping one pixel at a time.

Normally printf just dumps text top-to-bottom. ncurses is a library that gives you full control over the terminal — you can move the cursor anywhere, draw boxes, handle keypresses, create menus. Think of it as a toolkit for making terminal apps look like actual programs.

Now: The Two Algorithms
1. Bresenham's Line — Draw a straight line on a grid
The problem: You want to go from point A to point B on a grid of characters. You can only move one cell at a time. How do you decide: go right, or go diagonal?

The idea — think of it like walking on tiles:

Imagine walking from (0,0) to (4,2).
True path is a slope of 0.5 (rise/run).

Step 1: move right → true y should be 0.5, we're at 0. Error = 0.5
Step 2: move right → true y should be 1.0, error = 1.0 → step down! Error resets
Step 3: move right → true y should be 1.5, error = 0.5
Step 4: move right → true y should be 2.0, error = 1.0 → step down! Done.

Result: (0,0) (1,0) (2,1) (3,1) (4,2)  ← a diagonal line!
The code — with every line explained:

c
void draw_line(int x1, int y1, int x2, int y2, char ch) {
    int dx  = abs(x2 - x1);   // total horizontal distance
    int dy  = abs(y2 - y1);   // total vertical distance
    int sx  = (x1 < x2) ? 1 : -1;  // are we going right or left?
    int sy  = (y1 < y2) ? 1 : -1;  // are we going down or up?
    int err = dx - dy;         // error accumulator (starts as dx-dy)

    while (1) {
        plot(y1, x1, ch);               // draw current point
        if (x1 == x2 && y1 == y2) break; // reached the end, stop

        int e2 = 2 * err;               // double the error (avoids fractions)

        if (e2 > -dy) {   // need to step horizontally?
            err -= dy;
            x1  += sx;
        }
        if (e2 <  dx) {   // need to step vertically?
            err += dx;
            y1  += sy;
        }
    }
}
The key insight: err tracks whether we've drifted more horizontally or vertically. We multiply by 2 to keep everything integer — no floats, no sqrt, very fast.

2. Circle — Distance formula approach
The problem: A circle is "all points exactly distance R from the centre." On a grid of characters, you can't hit exactly R — so you check: is this cell close enough to radius R?

For every cell (col, row):
    dx = col - centre_x
    dy = row - centre_y
    dist = sqrt(dx² + dy²)

    if |dist - radius| < 0.6  →  draw '*' here
Why 0.6? Characters are about 2× taller than wide. If you use 0.5, the circle looks like a tall oval. The 0.6 threshold + a * 0.5 on dx corrects for that aspect ratio.

c
void draw_circle(int cx, int cy, int r, char ch) {
    for (int row = cy - r; row <= cy + r; row++) {
        for (int col = cx - r*2; col <= cx + r*2; col++) {
            double dx   = (col - cx) * 0.5;  // aspect ratio fix
            double dy   = (row - cy);
            double dist = sqrt(dx*dx + dy*dy);
            if (fabs(dist - r) < 0.6)        // close enough to ring?
                plot(row, col, ch);
        }
    }
}

This is important to understand conceptually before you look at the ncurses code.

When you DELETE or MOVE a shape, you don't try to "erase" it.
Instead:

1. Wipe the entire canvas to spaces.

3. Re-draw each one from scratch.

    draw it onto canvas

This is called "immediate mode rendering."
It's simple, correct, and used in real game engines too.
